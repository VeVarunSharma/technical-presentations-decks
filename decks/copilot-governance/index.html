06 · Permissions

deny → ask → allow

The strongest matching rule wins, and managed approval cannot be bypassed by a remembered grant.

07
denyRead(~/.ssh/**)

Blocked even when another rule would ask or allow.

askShell(git push *)

Requires fresh one-time human approval each time.

allowShell(npm test *)

Runs without a prompt when no deny or ask rule matches.

unmatchedsupported operation

Defaults to approval when managed rules or an allowlist exist.

10 · Eligibility filter

Match the server identity, regardless of source

Direct, session, workspace, and plugin-provided servers use the same documented allow/deny gate.

11
Open with exceptions

Omitting the allowlist permits servers subject to deny rules

This maximizes flexibility but gives administrators the least positive control over external tools and data sources.

"deniedMcpServers": [...]
serverUrlRemote HTTP/SSE server; wildcard patterns supported.
serverCommandExact local stdio command and arguments; no wildcards.
serverNameFallback identity; weaker than URL or command matching.
Deny wins. Trusted first-party Copilot MCP servers are exempt. GitHub recommends managed settings over registry-only restriction.
11 · Packaging versus policy

Plugin MCP is a distribution choice

It changes lifecycle and supply-chain governance—not the fundamental risk of the server.

12

Supply chainReview server identity and configurationReview marketplace, plugin identity/version, and server identity

A trusted marketplace answers “where did the plugin come from?” The MCP allowlist answers “may this server identity connect?” Current documented settings do not make provenance-specific MCP allow rules.
